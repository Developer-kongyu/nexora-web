# Nexora Web 代码系统学习方案

> 制定日期：2026-09-06。适用项目：`twitter-clone-web`。本方案依据当前源码、现有 15 章教程和项目目录说明编排。
>
> 学习目标：能够独立解释主要代码链路、定位常见问题，并按照现有架构完成一个有验证的小功能。课程安排是建议节奏，不是“固定时间内精通全部代码”的承诺。

## 先确定学习方式

建议采用 **8 个阶段、40 次学习** 的安排。每周 5 次，每次约 90 分钟，另用 1 小时复盘，8 周约 68 小时；某阶段没有达到验收标准，就为该阶段增加练习时间。每天只有 45 分钟，可以把一次学习拆成两天。

暂按“接触过 HTML、CSS、JavaScript，React 和 TypeScript 还不熟练”设计。已经能独立写 React 表单和列表，可以通过第一阶段自测后直接进入第二阶段。完全没写过 JavaScript，则先完成下面的预备检查。

学习中使用三份资料：

| 资料                                                          | 用法                                                       |
| ------------------------------------------------------------- | ---------------------------------------------------------- |
| [现有初学者教程](./tutorial/README.md)                        | 教材：理解概念和为什么这样设计。按本方案对应章节阅读。     |
| [项目目录结构与文件职责详解](./项目目录结构与文件职责详解.md) | 文件索引：遇到陌生文件时查职责与关联，不需要从头背到尾。   |
| [README](../README.md)                                        | 启动与命令参考：运行方式、环境配置、真实后端与 Mock 切换。 |

每次围绕一个可以观察的行为学习，例如“点击正在关注后，哪个 URL 参数变化、发出哪条请求、更新哪份缓存、渲染哪个组件”。先把一条链路走通，再逐渐增加分支。

## 预备检查：是否需要先补基础

在进入 40 次学习之前，尝试独立完成以下小题：

- 给一组帖子对象，用 map 提取标题、filter 筛出含图片的帖子。
- 解释对象解构、数组展开、可选链、空值合并运算符。
- 写一个 async 函数，等待 Promise 并在失败时进入 catch。
- 把一个函数从文件 A 导出，在文件 B 导入调用。
- 用 TypeScript 定义 Post 接口和 Loading/Success/Error 联合类型。
- 用 HTML 写带 label 的输入框，使用 CSS Flex 或 Grid 排列两个区域。

如果前三项很吃力，先补变量、函数、对象、数组、模块、Promise 和 async/await。只有 TypeScript 不熟可以在第一阶段跟着源码补。这里不要求先学完整本 JavaScript 教材。

**预备验收：**能解释一段“数组转换 + 异步请求”的代码，而不是只能照着复制。

## 每次 90 分钟怎么用

| 时间    | 动作                                         | 要留下的东西                         |
| ------- | -------------------------------------------- | ------------------------------------ |
| 10 分钟 | 不看笔记，复述上一次的链路                   | 一段自己的解释，指出仍不清楚的地方   |
| 20 分钟 | 读对应教程与少量源码                         | 标记入口、关键类型、调用者和调用对象 |
| 20 分钟 | 运行页面，观察 DOM、URL、Network、Query 缓存 | 一个具体现象及证据                   |
| 30 分钟 | 完成一个小实验或解释一个测试                 | 可复现的操作步骤、观察结果或局部修改 |
| 10 分钟 | 回答“为什么这样写”并记录                     | 一条结论、一个疑问、下一步           |

工作日读主链路；每周复盘把分散认识连接起来。通常一次重点阅读 3～6 个文件，复杂文件只跟踪当前行为涉及的函数。

### 每个文件固定问六个问题

1. **谁调用它？** 从路由、import 或事件处理找到使用方。
2. **输入是什么？** Props、URL 参数、表单值、API 请求参数分别是什么类型？
3. **状态由谁保存？** React state、URL、TanStack Query、Zustand、模块变量有什么区别？
4. **它做了哪些外部操作？** HTTP、Socket、剪贴板、文件选择、导航、定时器等。
5. **成功与失败怎么影响界面？** 加载、空值、权限、错误、重试分别走哪里？
6. **有什么验证证据？** 现有测试覆盖了什么；哪些行为需要自己观察？

遇到不懂的函数，先看调用点和输入/输出，再追实现。长组件先列出查询、写操作、事件和渲染分支，避免在 JSX 中迷路。

**第一天启动步骤：**

在 PowerShell 中进入项目，先看当前状态与版本：

```powershell
Set-Location 'C:\Users\lct_f\Desktop\X项目\twitter-clone-web'
git status --short
node --version
npm --version
```

项目要求 Node >=22.12.0、npm >=10。已有依赖可先使用；若缺少依赖，再执行 npm ci。

独立学习可以使用 Mock。在 .env.local 中设置下面三项；已有文件时只更新这些键，保留其他配置：

```dotenv
VITE_ENABLE_MOCK=true
VITE_API_BASE_URL=
VITE_SOCKET_URL=
```

然后启动：

```powershell
npm run dev
```

访问 [本地首页](http://localhost:5173/home)。修改 env 后要重启开发服务器。Mock refresh 可直接返回固定用户，因此“能直接进入首页”不能用来证明正式匿名权限行为。

开始实验前辨认并保留现有未提交修改。本次扫描时 README、PROJECT_TREE、tutorial 及目录说明已有工作区内容。创建学习分支只是记录练习的方式，不会自动隔离原来的未提交修改；本方案只给练习安排，没有替你切换分支或修改业务源码。

## 当前项目的学习边界

这些提醒直接来自本次项目审阅：

- **Mock 是学习工具。** 固定认证、简化推荐、假上传进度不能证明真实后端能力。模块内存状态会在同一浏览会话中保留；测试初始化同时调用 server.resetHandlers 与 resetMockState，分别恢复处理器与业务数组/Map。
- **DTO 有些是手写的。** generated/openapi.d.ts 目前只有空占位；学习接口时看领域 types、API 封装和测试，再与可用的正式后端契约核对。
- **有 UI 不代表全部交互已实现。** 首页侧栏推荐、社群部分榜单是演示逻辑；视频进度和时间部分为固定值；消息入口有提示占位。
- **已有测试的覆盖有限。** PostCard 测试覆盖导航和展示，MediaViewer 测试不证明实际播放/下载；E2E 当前是两条冒烟用例。
- **生产模式与 test 模式不同。** 普通生产 build 不会因 VITE_ENABLE_MOCK=true 就自动启动 MSW；mountApplication 还检查 DEV/test 模式。
- **旧文档是辅助资料。** 某些验证报告记载历史依赖安装失败，本地已有 node_modules/dist 并不能替代本次检查，也不能用旧失败推断现在仍失败。

阅读代码时同时记录“设计上希望如此”和“当前具体实现如此”，特别是缓存、权限、批量事务与实时补偿。

## 如何检验自己确实学会了

对一个代表功能，按下面四级自评：

| 等级      | 能力                           | 例子                                          |
| --------- | ------------------------------ | --------------------------------------------- |
| 1：能找到 | 知道功能入口和相关文件         | 找到首页 Query Key 与请求端点                 |

| 3：能定位 | 从现象用证据缩小到具体层或函数 | 判断结果不更新是数据、Adapter 还是缓存问题    |
| 4：能修改 | 独立完成变更并验证关键行为     | 完成搜索错误/重试体验，解释测试能捕捉哪类回归 |

结业目标：启动、请求、认证达到至少第 3 级；对一个自己选择的小功能达到第 4 级。复杂社群管理和上传流程可先达到第 2 级，后续继续深入。

**最终自测问题：**

- 从 /home 到一个帖子出现，依次经过哪些文件？
- 同样是“状态”，为什么有的在 URL、有的在组件、有的在 Query、有的在 Zustand？
- CSS Modules 改变了什么，PostCSS/Autoprefixer 又处理什么？
- 响应包络在哪解开，DTO 在哪变成 UI 模型？
- 登录、refresh、用户卡读取、引导路由各自负责什么？
- 注销之后，旧 refresh 为什么不能覆盖新会话？
- 帖子 id 与 contentPostId 为什么不能随便互换？
- 上传成功、处理 READY、草稿已保存、帖子已发布有什么区别？
- 部分批量操作失败时，应该保留哪些数据与反馈？
- 如何证明某个功能正常，而不只是“页面看起来正常”？
